# M03 — Persistence and Recovery

**ID:** M03
**Status:** DONE
**Depends on:** M02
**Validation:** make milestone ID=M03
**Handoff:** AI/handoffs/M03-handoff.md

## Objective

Сохранять каждое принятое действие атомарно и возвращать игру вместе с контекстом после закрытия.

## Scope

- Реализовать предложенные ARCHITECTURE repository/actor, versioned Codable envelope, command ID, active session, latest completed session, последние настройки и независимый usage ledger.
- История snapshots активной/последней сессии для точной отмены и восстановления; не вводить скрытый предел сетов или действий.
- Транзакция сохраняет счёт, service anchor, правила, session status и undo-контекст вместе. UI сообщает успешное действие после фиксации.
- Безопасное чтение версии, восстановление последнего согласованного состояния, обработка недоступной записи и повреждённых данных без молчаливого пустого матча.
- Интерфейсы entitlement/usage пока допускают тестовый источник; StoreKit и точная коммерческая политика принадлежат M08.
- Команда удаления игровых данных очищает active/latest/undo/settings атомарно; отдельный usage ledger не сбрасывается неявно. Конкретная политика удаления trial задаётся H4 и подключается в M08, экран удаления — M07.

## Non-goals

- Облачная синхронизация, аккаунт, полноценная история матчей и сервер.
- Ретроактивное пересчитывание played history по новым правилам.

## Acceptance criteria

- [ ] Закрытие/повторное открытие восстанавливает одинаковые очки, сеты, подающего, стадию deuce, номер в серии и доступную отмену.
- [ ] Внедрённый сбой записи не оставляет половину транзакции и не показывает успешное начисление; повтор command ID не добавляет очко повторно.
- [ ] Undo через завершение гейма/сета и последнего розыгрыша американо возвращает полный предыдущий snapshot, включая status и service.
- [ ] Тесты покрывают round-trip обеих моделей, schema mismatch, повреждение основного файла и recovery без молчаливого сброса usage; если точные данные ledger утрачены, неопределённость показана явно.
- [ ] Undo восстанавливает игровой snapshot, сохраняя актуальный ledger и ever-counted game IDs; Finish → Undo → Finish не возвращает и не удваивает trial-единицу.
- [ ] Тесты проверяют наблюдаемое поведение и регрессии этого этапа; `make milestone ID=M03` проходит на clean `REVIEW` HEAD с обязательными тестами без failures/skips.

## Validation
