# M06 — Score and Settings Correction

**ID:** M06
**Status:** DONE
**Depends on:** M05
**Validation:** make milestone ID=M06
**Handoff:** AI/handoffs/M06-handoff.md

## Objective

Исправлять любые введённые данные атомарным черновиком без скрытого пересчёта сыгранного.

## Scope

- Menu → Edit score / Serving / Rules: текущие очки и deuce phase, геймы, список сетов с add/edit/remove, порядок и текущий подающий.
- Американо: обе суммы, N, B, текущий подающий и позиция следующего розыгрыша внутри серии.
- Новый режим/формат задаётся в явном replacement draft той же sessionID; показать целевое состояние до сохранения, сохранить исходное до commit и для Undo. Не преобразовывать автоматически геймы в rally points.
- Правила действуют с текущего явно подтверждённого состояния вперёд. Валидатор показывает конфликт и необходимые поля, но не выигрывает гейм/сет за пользователя.
- Back/Cancel оставляют исходник; Save сохраняет весь draft одним действием. Активный редактор не допускает начисления очков за ним.
- Ручная коррекция чисел не угадывает server history; пользователь подтверждает service anchor, если он стал неоднозначен.

## Non-goals

- Удалённая синхронизация и слияние правок нескольких часов.
- Скрытые конвертации форматов, удаление результата без явного действия.

## Acceptance criteria

- [ ] Исправляются все введённые при создании и игре поля; UI не требует начать новую платную/пробную session ради исправления.
- [ ] Тесты покрывают N ниже суммы, B ниже текущей позиции, invalid AD/deuce phase, completed-set insertion/removal и несовместимую policy.
- [ ] Save/Cancel/ошибка сохранения сохраняют целостность; после Save Undo возвращает счёт, формат, правила, очередь и позицию до правки.
- [ ] После correction и relaunch данные совпадают; usage ledger и ранее подтверждённая покупка не меняются от правки.
- [ ] Тесты проверяют наблюдаемое поведение и регрессии этого этапа; `make milestone ID=M06` проходит на clean `REVIEW` HEAD с обязательными тестами без failures/skips.

## Validation

`make milestone ID=M06`. Обязательные проверки и evidence выполняются в одной Builder-сессии.
