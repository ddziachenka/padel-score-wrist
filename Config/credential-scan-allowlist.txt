# Config/credential-scan-allowlist.txt
#
# Exact files that the credential scans in verify-static.sh may accept for ONE
# named rule each, because the file is a legitimate committed artifact that only
# looks like a secret. Prefer removing the file over listing it.
#
# Format:
#
#   <repository-relative path> | <rule> | <specific reason> | <expiry YYYY-MM-DD>
#
# <rule> is exactly one of:
#
#   filename         the file's NAME matches a credential filename pattern: a model
#                    named Credentials.swift, or a pinned public .cer certificate.
#                    A private key, keystore, signing identity, provisioning profile,
#                    or SSH key name can never be listed.
#   google-api-key   a Google client key designed to ship inside the app, such as the
#                    one in Firebase's GoogleService-Info.plist.
#   url-credentials  user:password text inside a URL in documentation or a fake test
#                    fixture.
#
# No other rule can be listed: a private key or a provider secret token is a secret
# wherever it appears, so move it out of the repository and rotate it.
#
# An entry excuses that path from that rule and nothing else. The file is still
# scanned for every other rule, and the same bytes anywhere else still fail. Paths
# are exact (glob characters are rejected), reasons must be real, and expiry dates
# must be in the future, so an exemption is reviewed rather than forgotten.
#
# Example:
# App/YourApp/GoogleService-Info.plist | google-api-key | Firebase iOS key, restricted to this bundle ID in Google Cloud | 2027-10-01
